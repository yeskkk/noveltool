# NovelTool v0.20.0 — 本地小说编辑与小模型辅助工作台

NovelTool 是单进程 Python 程序，用浏览器连接本机 WebUI，通过兼容 OpenAI Chat Completions 格式的接口请求模型。它既可导入已有小说并分析设定，也可由想法创建初始设定；之后支持多个续写/返修候选、手工拼装、正文版本与撤销、设定增量同步和提示性一致性检查。

版本差异见 `CHANGELOG.md`，本版实际验证范围见 `TEST_REPORT.md`。默认使用“小问题”协议：不要求模型编写 JSON，程序将短回答转成可校验条目；严格 JSON 协议仍可在项目设置中选择。中文转换只作用于新模型短答和候选，可关闭；原始来源和人工正文不自动翻译。

## 1. 安装、首次运行与升级

环境：Linux 或 WSL，Python 3.11+。需要 `flock` 项目文件锁；实际测试环境为 Linux/Python 3.13。运行时依赖 FastAPI、uvicorn、Pydantic 和 httpx。不需要 Node.js、向量库、模型 SDK、账户系统或外部网页资源。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
python -m noveltool --project ../projects/my_novel.sqlite3 --create --title '我的小说'
```

浏览器打开 `http://127.0.0.1:8765`。首次安装需要取得依赖，安装后除请求配置的模型服务外，无须联网。模型可以在本机或用户指定的其他服务上；小说会发送到该地址，使用前请核对。

重新打开项目时不加 `--create`：

```bash
python -m noveltool --project ../projects/my_novel.sqlite3
```

终端按 Ctrl+C 正常退出会保存内存修改。关闭浏览器不等于退出服务。源码和数据库建议放在不同目录；升级时停止旧进程，解压新源码并安装，再打开原数据库。程序先验证旧项目，再用 SQLite backup 生成 `*.before-schema-*.bak`，然后事务性升级。升级是单向的，旧程序回退需要旧备份。

一个进程只打开一个项目。同一数据库不能被两个 NovelTool 进程同时打开。默认只监听回环地址，不适合直接暴露到公网；没有多用户权限系统。API key 通过 `NOVELTOOL_API_KEY` 或设置指定的环境变量提供，不写进 SQLite 或日志请求头。

## 2. 按什么顺序使用

### 2.1 已有小说

1. **项目设置**：应用服务 Base URL（如 `http://127.0.0.1:8000/v1`）、写作模型和分析模型名称，再到“模型测试”检查连接。
2. **导入与分块**：选择 TXT 与编码，预览并核对乱码；确认后同时保存原始文件字节、规范化正文和导入 Revision。自动模式识别 BOM，否则严格尝试 UTF-8，不能保证识别所有旧编码。不要跳过预览。
3. **创建分块计划**：核心切片按顺序覆盖全篇一次，前置重叠片段只帮助理解。超长自然段可切成多个引用片段，不改正文。修改正文后要创建新计划或使用“设定同步”。
4. **分析**：可以预览并运行单块，也可以执行全书任务。计划块先按事实、关系、叙事分组；默认协议再将核心文本拆成约 400 字的小段，逐个询问名称、身份、阶段状态、事件等。每个回答立即保存检查点；一个回答失败不丢失其他成功条目。预览显示微任务计划，真实逐次请求见步骤/调用日志。
5. **设定与时间线**：先在待审观察中核对条目和原文，勾选已核实的条目，再点击接纳。小问题输出的“来源”只是程序绑定的输入小段，不是证明陈述成立，因此未经接纳不会进入自动设定和写作上下文。只有明确名称匹配才归并，歧义/冲突保留；人工设定不被重分析覆盖。
6. **状态/上下文**：指定正文位置，检查该处状态和模型将读取的实际资料。看到哪些资料被省略后，再决定是否改设定、缩短范围或调整预算。
7. **续写/返修**：输入本次建议及 A/B/n；候选各自独立调用模型。选中候选片段插入最终草稿，或直接手工写最终稿。确认之前，候选不改变小说。
8. **确认、同步、核对**：正文先独立事务保存，随后按勾选项启动增量设定同步。返修后还可运行后文一致性检查；提醒不会自动改后文。

### 2.2 只有想法

空正文项目在“构思”页输入创意。默认分别询问一句构思概要、少量人物名称、各人的身份/目标、关系、线索和风格；每次一个短问题，不让模型组装整张表。Python 组装可编辑提案，普通表单允许删改，不要求用户写 JSON。

完成的部分会逐步保存。网络中断后可继续未完成步骤；完全相同的已完成步骤复用检查点。若用户已经手工改过提案，续跑被拒绝，防止新响应覆盖编辑。部分提案也可手工补齐后确认，但必须明确勾选接受未完成提案。保存草稿不写正式设定；明确确认才原子写入，且不建立已发生事件。已有正文项目不允许通过构思入口覆盖初始化。

## 3. 界面中几个容易混淆的状态

**浏览器输入、程序内存、数据库是三层。** 配置表单要点击“应用到内存”，才由后端校验并改变当前配置；默认每 60 秒批量事务落盘，可点击立即保存。候选拼装草稿在停止输入约 900 毫秒后同步到程序内存，再按集中保存周期写盘。未发送的浏览器输入无法进入服务器备份。

**最终草稿不等于正文。** 只有“确认追加/替换”才生成正文 Revision。正文确认、手工修改、撤销和导入立即事务保存；AI 分析不在正文事务里。即使模型随后超时或解析失败，已确认正文也不回滚。

**流程覆盖不等于事实正确。** 只要一个小步骤仍未完成，其分析就不计作完整覆盖；成功片段仍可单独审核。全部步骤完成也只说明预定问题获得了回答，不保证穷尽全部人物和事实。小问题条目和经过修复的严格输出都需核对。人物说谎、梦境、倒叙及不可靠叙述仍需作者判断。

## 5. 从启动到保存，一步步怎样运作

启动先取得操作系统文件锁，拒绝误覆盖、错误文件和未知数据库版本。打开时检查 application_id、元数据、配置、SQLite 完整性及外键；有旧结构则备份后升级。载入正文有效块、配置、设定及工作流索引；原始模型响应、旧正文块和完整历史按需读库。

Web 变更请求检查同源令牌和版本号，再进入服务方法。短时 `session.lock` 保护共享状态；锁内创建快照、版本检查与事务，**等待模型时绝不持有项目锁**。`model_gate` 串行限制模型工作，避免多个流程挤占同一个小模型。无需 Celery、Redis 或多进程队列。

模型的小问题检查点属于昂贵工作结果，每完成一步立即短事务保存；不是每 60 秒才记一次进度。配置和草稿等仍按周期集中保存。

定时任务在存在 dirty 项时批量 UPSERT/UPDATE，事务成功才清除标记；失败保留内存修改与错误状态。正文事务会把相关任务确认状态一起提交，防止正文更新而任务仍未确认的半成品。操作完成时再更新内存投影。强制终止只能保证已经提交的数据库内容，尚未落盘的配置/草稿可能丢失。

## 6. 正文与范围返修为什么可撤销

每个 Block 的文字不可变，分隔符、缩进及换行也属于正文。替换首尾块的部分内容时，程序计算 prefix + replacement + suffix，旧块退役、新块创建；范围外文字保留。Revision 记录旧/新块和锚点，不复制全书作为每次快照。

浏览器选区是 UTF-16 偏移，JS 转为 Unicode code point 再提交；后端核对选区文本和版本，避免 emoji 附近偏移错位。逻辑行按实际 `\n` 计算，不是浏览器自动折行。撤销恢复旧块和真实空白，且可连续撤销。

生成任务同时固定正文版本、设定版本、任务参数、选区和上下文。生成后版本变化，不能直接确认旧候选；草稿保留供人工核对。重复确认同一结果是幂等操作，不重复追加。

## 7. 模型调用与“半截 JSON”

请求采用 `POST {base_url}/chat/completions`，`stream=false`，不依赖 tools、response_format 或服务端 JSON Schema。所有调用经过 `llm.py`，限制 HTTP 超时/响应大小、不自动跟随重定向，日志排除 Authorization 并对环境密钥回显脱敏。

有三个不同的限制，不能混为一谈：

- **总上下文**：输入和输出合计，用户设置 context_window 和安全比例。
- **本次输出上限**：请求中的 max_tokens；旧默认分析 1536、构思 3072，所以总上下文未满也会停止。
- **服务端/模型自身停止**：EOS、停止词、服务端生成限制、reasoning 开销等。本程序不假定所有兼容端点都准确返回 finish_reason。

每次调用保存 requested_max_tokens、输入估计、finish_reason 和服务报告 usage。即使输出截断或只用在 reasoning 上，也先记录用量，再返回错误；reasoning_content 不当作小说或事实。不开内容日志时仍保留这些诊断元数据。

结构化调用遇到 `length` 或返回未闭合 JSON 时，可以按设置在安全上下文内增大预算重试（默认一次、上限 8192）。这是**从头重新请求同一小任务**，不把两次尾巴拼接，也不补造缺失的引号/事实。新响应仍要完整校验，重新生成的结果提示核对。网络错误、拒绝或不存在的证据，不通过输出重试掩盖。普通写作不会因此自动重试并替换已有候选。

### 默认小问题协议怎样“宽进严出”

每小段默认最多 400 个 Unicode 字符，少量前文只供衔接。问题例如“这里有哪些人物，最多 3 个，名称一行一个”“只说林此刻的处境”“用一句话说发生了什么”。身份、关系、事件和风格各自提问；输出预算默认每问 1536 token，可在项目设置单独修改，不再被旧的整个块 1536/构思 3072 预算压低。重试最多 0～2 次，仍受安全上下文及输出重试封顶限制。

接收层容许普通短句、分行名单、常见 Markdown 表格，以及常见 JSON 包装。名称必须实际出现于分析小段；创意提案才允许新增名称。完整小条目可以从截断的列表中救出；半个字符串、未结束句子和未能识别的条目隔离保存。不会补造引号把半个名字变成“事实”，也不会把未知项猜成一个合法 ID。

程序负责字段名、关系类别、内部 UUID 和正文位置，并用严格类型检查构造后的每条结果。“宽进”只针对表达方式，不代表跳过引用检查或接受模型操作数据库。明确的 `<think>` 区域不当作答复。一个小问失败，其他问继续；网络/配置错误停止发送后续请求，已完成步骤保留。

`model_steps` 保存每次问答的状态、结果、用到的模型调用和警告。已成功步骤按问题、原文、来源位置、模型和预算指纹复用；失败或部分步骤不能作为成功缓存。重试同一原文不会取消用户已经做出的同内容审核。暂停在下一小问之前生效；不能保证立即中断服务器已经开始的计算。

### 严格协议与诊断

模型测试页的“小段分析”跟随所选协议；“仅本地校验 JSON”仍专门用于调试严格输出，不要求正常用户写 JSON。严格协议适用于更守格式的模型；一致性检查目前也仍使用严格结构化返回，并非所有工作流已改为微问题。

当前严格分析路径依次执行：提取唯一 JSON 根 → 重复键/嵌套深度检查 → 单引号/尾逗号受限修复 → 严格 Schema → 原文证据/实体引用校验。安全的纯格式错误最多额外修复两次；语义错误不让格式模型编造依据。最终失败仍保存原始响应和错误，不写正式设定。

### 可关闭的中文转换如何工作

项目设置的“中文项目”默认勾选。它应用于 **小问题协议的描述性短答**（身份、状态、事件、构思描述等）以及 **新生成的续写/返修候选**；严格 JSON 提案/分析、原文证据和一致性结果目前不经过这个转换器。姓名列表、数据库标识、人工输入的创意、草稿和已确认正文都不自动翻译。刻意使用外文对话或创作非中文作品时应关闭该选项，再创建新生成任务；已有任务使用其配置快照。

程序先按汉字/其他文字和片段比例做启发式检测，已知外文姓名不算正文偏外语。一段中文后突然出现英文，可以在句子级被识别。短描述里的 `journalist` 等标签也可转换；检测不是通用语言识别，仍可能误判或漏掉。

待转换文本按句子/换行再拆为最多 360 字符的小段，每份回答最多处理 64 个外语小段。每问只要求忠实中文翻译，不要求 JSON；使用分析模型，没有分析模型时才使用写作模型。每段最多重试项目设置的次数，实际输出仍受预算限制。已有中文和空白分隔尽量保持，已知名称和阿拉伯数字必须保留。未闭合 JSON、半截译文、名称/数字改变、仍主要为外语、明显过短/过长都会拒绝该段转换，并保留其转换前文本。跨片段再核对名称和数字，失败时整份回退。

`language_outputs` 保存转换前文本、各段尝试/状态、最终显示文本和模型调用关联。成功段是独立检查点，部分失败不会抹掉成功段。若程序中断，未完成余文仍可从转换记录中找到；这不意味着服务器正在计算的请求已被取消。小问题的中文转换未完成会标为部分完成，成功其他条目仍可审核。

候选页显示中文转换警告和转换前文本，提供“转换前文本采用到草稿”。候选的 A/B 字数在转换后重新计算，仍需人工确认才能改正文。候选翻译失败不会取消本来可用的外文候选。翻译改变了长度或含义，最终选择权在作者；名字/数字检查也不能证明全文等义。

## 8. 观察、人工设定、时间位置

严格模式中模型可返回 B001 等临时引用，摘录必须实际存在。小问题模式不要求模型填写证据编号，而由程序把该条回答关联到本次核心小段，再转成不可变 block_id + 起止偏移。前置重叠不能单独变成核心事实。

小问题模式的来源仅说明“模型看了哪一段”，不是语义证明。所有这类观察都需人工审核后才成为自动设定。姓名原样匹配也不能解决叙述中的别名或同名歧义，仍允许人工修正。

自动观察只做确定性的名称/别名归并；同名歧义、不同值及冲突保持可见。人工设置是独立的 profiles/entries，并有自己的版本。正文、人工设定和自动推断不混在一段无法追溯的“总记忆”里。

位置状态先筛掉当前位置之后或来源失效的观察，再处理相对稳定事实和阶段变化。叙述顺序不等于实际故事时间，未知时间不自动猜成精确日期。全书已知的名字及全局人工设定仍可能被作者主动使用，不是严格的剧透隔离器。

## 9. 上下文与 n 个候选

`ContextBuilder` 获取任务、位置、选区、建议和相关实体，加入必需规则、紧邻文字、人物状态、直接关系、线索、摘要及风格，按预算去掉低优先级资料。必需选区放不下就报错，不静默截断。当前估算基于 UTF-8 字节和固定开销，刻意保守，但不等于真实 tokenizer；实际服务仍可能不兼容。

每个候选单独请求，默认顺序执行。候选失败不覆盖其旧成功尝试。字数定义为去 Unicode 空白后的 code point 数（含标点），不是英文词数，也不是 token。A/B/n 按任务快照保存，设置变化影响之后新任务。最终人工草稿超范围需要明确允许。

## 10. 增量同步与一致性检查

同步不是看到 block_id 还存在就复用。`semantic.py` 检查旧调用的**完整核心与重叠输入**是否依然存在、连续并紧邻，核心哈希一致后才复用旧分析身份和审核结果。失效范围另行补析。由返修引起的后文因果问题不等于源文本已变，需要独立检查。

一致性检查固定最新一次范围修改前后文本，按预算扫描后续正文，每条问题必须引用真实修改依据和后文依据。成功检查单元与问题列表分开保存，暂停/失败可续跑。没有提醒不等于证明小说一致；只核对显式线索，不自动级联改文。

## 11. 备份、恢复和故障排查

“项目维护”可下载完整 SQLite backup，先保存已到服务器的内存修改；备份包含项目历史、原作、候选和保留的日志，无须另带 WAL。可能包含私人小说内容，不要公开上传。

不开原始内容日志时，模型步骤仍保存用于恢复的派生短答和引用；它们是项目数据，不是调试日志。原始完整回复按日志设置保留。

转换前的可用短答/候选和中文显示文本保存于 `language_outputs`，属于可逆工作结果；即使关闭调试日志也会保留。关闭调试日志不是删除模型派生结果。页面步骤审计/候选详情可对照，完整原始 HTTP 响应仍按日志开关处理。

进程中断后运行中任务会标为 interrupted/pending，重新开始按已保存检查点恢复，不声称服务端计算已经取消。出现 half JSON 时，先看“模型测试 → 最近调用”：max_tokens、completion_tokens、finish_reason 是否提示长度限制；然后查看项目维护中原始响应。增大输出上限并不保证弱模型会遵守复杂格式，更不保证内容质量。

`finish_reason=stop` 只代表 API 报告正常停止，不代表 JSON 必然完整。输出只有思考或英文也不是成功提取。默认小问题模式减少格式负担；中文转换采用同一个配置的分析模型，不能保证同一个弱模型翻译时一定更可靠。转换失败会保留原文和警告，而不是再次把全部流程卡死。普通文本即使正常结束，也可能在语义上没说完；程序不能可靠自动判断所有这种情况。

## 12. 测试和局限

```bash
python -m pytest -q
```

测试覆盖项目迁移/保存、范围编辑与撤销、过期候选防护、导入、分块、分析证据、人工设定保护、构思、生成确认、同步、检查以及截断诊断。模型测试使用确定性 HTTP 测试端点，不连接真实小模型；回归通过不能保证所有本地服务兼容或创作质量。

本版测试覆盖常见名单/短句、从截断列表救出完整项、微步骤失败后只补问一次、原文改变不复用旧回答、暂停续跑、构思部分提案及手工编辑保护，还覆盖混合中英文检测、短标签、分段转换失败原文保留、数字/姓名检查、关闭原始日志仍可对照、转换后候选重新计数。旧严格 JSON 用例明确使用 strict 模式，新用例独立验证默认 small 模式。

小问题模式用更多调用换取单次任务简单，速度/服务费用可能增加；默认每小段最多 3 个实体，并不是穷尽所有文学细节的分析器。短片段也可能缺少代词或隐喻的上下文；应通过人工审核和设定修正补足。本版未连接用户真实模型，也未进行新的真实浏览器验收，不沿用旧版覆盖率或验收数字。


## 13. 升级后针对弱模型的起步操作

从 v0.17.0 升级会备份并迁移，旧正文和历史保留；新配置默认使用 small 和中文转换。停掉旧服务、安装新源码再打开旧项目，不要加 `--create`。可以先到模型测试页用一小段正文试“小段分析”，或在空项目尝试只有一两个核心人物的构思；不要一上来重跑全书。

设置中的“小问题初始输出 token”是实际请求配额，默认 1536，“输出重试封顶”默认 8192，“输出重试次数”默认 1。需要更多推理配额时可以手工把小问初始上限改到 3072 或 4096，结合调用日志的 requested_max_tokens、usage 和 finish_reason 核对；这是调试起点，不保证模型一定能答完。不要只增大总上下文却忽略本次输出上限。默认小问来源 400 字、最多 3 个实体，可按模型表现调整。

旧的失败记录不会自动改成成功，也不会在升级后后台重跑整本书。配置改变后老任务可能需要重新建立；已经有手工编辑的构思提案不会被自动续跑覆盖。保留原提案或草稿后新建一次任务更容易比较效果。严格 JSON 的本地校验按钮只用于诊断，不是正常使用必须通过的一道关卡。
